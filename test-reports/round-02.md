### MR-010：隐蔽窗隐藏后重开保留旧内容

- **前提/步骤**：阅读 A 并首次 UI 打开隐蔽窗 → 用隐蔽窗关闭按钮隐藏 → 主窗进入 B 的真实正文 → 点击“隐蔽阅读”。同书对照：再次隐藏，在主窗将 A 滚到另一段并等进度保存，再重开；另用原生 Ctrl+Alt+M 重开复现。
- **预期**：已有隐蔽窗重新显示时按当前阅读书籍、章节及位置更新，而不是仅显示首次打开的旧内存内容。
- **实际**：主窗 B 为《暗体》第963章，隐蔽窗仍是 A 的“第七十七章 破壁（二）”第 4/39 段，旧文本哈希未变。主窗 A 段索引 9 时，重开仍为旧 4/39 段；原生重开同样出现旧位置。
- **影响**：隐蔽阅读显示错误书籍/位置；没有据此宣称 SQLite 进度已丢失或被覆盖。
- **证据**：[B 主窗](evidence/round-02/r02-MR010-B-main-cropped.png) / [隐蔽窗仍 A](evidence/round-02/r02-MR010-B-shows-A-stealth.png)，[A 新位置](evidence/round-02/r02-MR010-A-main-new-position-cropped.png) / [隐蔽旧位置](evidence/round-02/r02-MR010-A-old-position-stealth.png)；`observations.json` 的 `MR010-cross-book-reopen-comparison`、`MR010-same-book-new-position-repro`、`MR010-native-repro-*`，以及原生记录。

### MR-011：一次透明度快捷键变化 20 个百分点

- **步骤**：已有可交互隐蔽窗，调整到“透明 65%” → 记录被动事件为空 → 原生按一次 Ctrl+Alt+↓ 并松开 → 观察 → 原生按一次 Ctrl+Alt+↑ 并松开。
- **预期**：一次按键按定义的 0.1 alpha 步长变化一次，即 10 个百分点；对应 65%→55%，反向一步恢复。
- **实际**：Down 仅录到一个 `stealth:opacity`、payload -1，实际 **65%→45%**，alpha 约 0.35→0.55。Up 只新增一个 payload +1 事件，又 **45%→65%**。不是长按或重复事件；当前正文文本未变。这里不推定重复处理的源码根因。
- **影响**：透明度调整幅度与一次操作不一致；边界钳制及保存恢复可用不抵消该问题。
- **证据**：[65% 操作前](evidence/round-02/r02-MR011-alpha65-before.png)、[一次 Down 后 45%](evidence/round-02/r02-MR011-alpha45-after-one-down.png)；`observations.json` 的 `native-state-MR011-before-down` / `one-down` / `one-up-repro`，`native.json` 的 `native-MR011-one-down`、`native-MR011-one-up-repro`。

### MR-012：顶栏拖动未移动并报权限错误

- **步骤**：显示可交互隐蔽窗 → 在顶端拖动条约 (25,5) 按住鼠标拖动 → 再从 (240,6) 拖动。使用实际 Win32 鼠标输入，不是 DOM 合成事件。
- **预期**：拖动声明为 `data-tauri-drag-region` 的顶栏时，原生窗口随拖动移动。
- **实际**：两次 Win32 矩形均保持 `(156,156)-(652,261)`。DOM 命中 `stealth-drag-bar`，mousedown/move/up 为 `trusted:true`；报 `window.start_dragging not allowed. Permissions associated with this command: core:window:allow-start-dragging`。
- **影响**：用户不能用现有顶栏调整隐蔽窗位置；不是点击穿透模式或目标被覆盖造成的未命中。
- **证据**：`native.json` 的 `native-drag-actual`、`native-drag-second`；`observations.json` 的 `actual-drag-region-DOM`；[前端错误摘录](evidence/round-02/app-console.json)、[隐蔽窗](evidence/round-02/r02-native-drag-diagnostic.png)。

### MR-013：关闭主窗后托盘无法恢复

- **前提/步骤**：当前进程已正常建过隐蔽窗，并将其隐藏 → 自有托盘左击恢复最小化主窗，确认此时恢复正常 → 原生 UIAutomation `WindowPattern.Close` 关闭主窗 → 左击自有托盘 → 再右击并实际点击“显示主窗口”。第二、第三独立启动均执行。
- **预期**：若应用仍运行，托盘已有且可点击的“显示主窗口”应恢复主界面；若关闭语义为退出，应正常退出。**不以“关闭未到托盘”本身判缺陷，也未要求尚未开放的关闭行为设置。**
- **实际**：关闭后主窗已从 Win32 枚举及 WebView2 target 消失，应用仍运行，只剩隐藏隐蔽窗。左击及“显示主窗口”后仍 `mainAvailable=false`、`appStillRunning=true`；“退出”则能结束应用。两个独立进程（39464、7576）一致。
- **影响**：关闭一次主窗后无法从现有托盘恢复主界面，只能退出再启动。
- **证据**：`native.json` 的 `native-run2-after-main-close`、`native-run2-closed-main-*` 及对应 run3 记录；菜单归属由自有 `#32768` / `MN_GETHMENU` / `GetMenuItemRect` 确认，[自有菜单截图](evidence/round-02/native-run3-closed-main-menu-show.png) 只证明菜单存在，恢复失败以操作前后原生记录为准。

### MR-014：首次加书成功但原按钮仍可点击

- **前提/步骤**：B 不在 QA 书架 → 真实搜索并进入 B 详情，978 目录及“加入书架”可用 → 点击一次“加入书架” → 不再点击，分别等约 1.8 秒、7 秒 → 返回书架核对，再从书架重新打开详情。
- **预期**：保存成功后当前详情立即转为“已在书架”并禁用加入按钮，避免让用户误以为没有保存。
- **实际**：辅助只读查询及实际书架均确认 B 已保存，但 1.8s/7s 后原详情仍“加入书架”、`disabled=false`。重新挂载详情后“已在书架”及禁用状态正常。正文链路可以完成；**不是保存失败，也未观察到重复入库**。
- **影响**：成功反馈和当前按钮状态错误，用户可能重复点击。
- **证据**：[首次点击后仍可加入](evidence/round-02/r02-readd-B-first-click-feedback-cropped.png)、[重新挂载后正常禁用](evidence/round-02/r02-existing-B-duplicate-add-disabled-cropped.png)；`observations.json` 的 `readd-B-before-first-click`、`first-click-1800ms-feedback`、`first-click-readonly-shelf-result`、`first-click-7000ms-feedback-without-second-click`、`candidate-UI-save-feedback-issue`。
