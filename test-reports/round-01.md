## 测试方法与夹具边界

- 使用现有 Node 的 CDP `Input` 操作真实 WebView2 的点击、输入、滚动和按键；操作后检查 DOM、截图、localStorage，以及 QA SQLite 的一致性检查点/辅助查询。
- 原生窗口、快捷键和托盘使用 Win32/UIAutomation；WebView2 的原生确认框使用确认按钮实际操作。直接 IPC 只用于诊断或建立下游夹具，不代替 UI 通过证据。
- 为避免同时请求全部外网源，启动前仅在 QA 副本禁用所有书源。随后经 UI 启用小样本，最后仅保留原有“奇怪小说”启用。**164 项加载成功不代表 164 项网络功能成功。**
- 正常新书详情被 MR-001 阻断后，将已经真实搜索返回的《不一样的三体》辅助保存到 QA 书架，验证下游功能。删除用例临时辅助保存另一真实结果《暗体》。这些保存操作 **不计“UI 加入书架”通过**。
- 《不一样的三体》来源“奇怪小说”，实际目录 93 项，测试读取 6 个章节缓存。工作库最终保留一本书、章索引 `4`（UI 第 5 章）、总目录 93、164 个源/启用 1 个、正文缓存 6、目录缓存 1；外观为深色、24px。
- 删除及重新获取测试后出现在线加载失败。停止 QA 后，将早先的 `before-restart.db` 恢复到 **QA 工作库**，保留真实缓存供复测；再次启动真实 WebView2 后确认缓存正文可读。这是夹具恢复，**不是在线抓取故障已经修复的证据**。

### MR-001：新搜索结果详情失败

- **前提/步骤**：QA 书架无目标书，只启用“奇怪小说” → 发现页输入“三体”并点搜索 → 等到 50 项及搜索结束 → 点击未在书架的结果。重新搜索后再次点击复现。
- **预期**：进入该结果详情，保留真实来源信息，能继续 UI 加入书架/阅读。
- **实际**：显示 `找不到该书籍信息`，没有加书操作；已在副本书架的同来源真实书籍则能显示详情及目录。
- **影响**：正常新书端到端链路不能完成。
- **证据**：[真实搜索](evidence/round-01/r01-absolute-source-search.png)、[详情错误](evidence/round-01/r01-actual-result-detail-error.png)；`observations.json` 的 MR-001 / `first-actual-result-detail`、`detail-missing-repro`。

### MR-002：隐蔽阅读入口失败

- **步骤**：在有真实正文的阅读页点击“隐蔽阅读” → 确认提示 → 再点一次。
- **预期**：正常打开隐蔽阅读窗并显示当前阅读内容。
- **实际**：两次均弹出 `打开隐蔽窗口失败`；辅助 IPC 诊断 `open_stealth` 返回 `Command open_stealth not found`。
- **影响**：隐蔽阅读入口不可用，后续窗口操作阻断。
- **证据**：`observations.json` 的 MR-002 / 两次 `stealth-ui-open-attempt-*` 及 `stealth-missing-command-auxiliary`。
- **复测注意**：仅修正命令名不能直接判通过。辅助调用已注册的 `open_stealth_window` 也曾未完成，见 AUX-01；须重测首次正常 UI 建窗。
