## 根因与最小修复

正常新书先在详情页获取目录，此时目录进入 `chapter_list_cache`，但书籍尚未入架，原有总章数更新没有对应书籍行。随后 `save_book()` 写入总章数 0，爬虫命中目录缓存直接返回，不再补齐总章数；因此正文和章索引正确，书卡却持续显示“尚未开始”。

- 在共享的 `Database::get_cached_chapter_list()` 中，读取并验证非空 `Vec<BookChapter>` 后，仅补齐该书为 0 的总章数。爬虫、入架与旧库初始化共用这一处逻辑，不重新请求外站。
- `save_book()` 入架后核对已缓存目录，返回实际数据库书籍，不再构造总章数/章索引均为 0 的返回值。重复保存保留数据库现有定位。
- `init_tables()` 在初始化已有库时检查总章数为 0 的记录，用有效缓存补齐，使已有问题书籍在首屏即可恢复正确展示。
- 不改书卡文案、IPC/类型/权限、SQLite 表结构、书源或外观设置；补齐不修改章节索引、章名、阅读时间、目录 JSON 和目录更新时间。无缓存、空目录、无效 JSON 或缺少章节字段时不猜测总章数。

仅修改 `src-tauri/src/db.rs` 与 `src-tauri/tests/integration_tests.rs`，未操作正式用户数据库。
